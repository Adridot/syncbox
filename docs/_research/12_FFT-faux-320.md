### Constat (faits sourcés)

**Le principe physique : tout encodeur lossy applique un filtre passe-bas caractéristique**
- *(Fait)* Un encodeur MP3 coupe les hautes fréquences au-dessus d'une fréquence de coupure dépendant du débit. La table par défaut de LAME : **CBR 320 ≈ 20 094-20 627 Hz**, V1 ≈ 19 383-19 916 Hz, **V2 ≈ 18 671-19 205 Hz**, V3 ≈ 17 960-18 494 Hz, V4 ≈ 17 249-17 782 Hz, V5/V6 ≈ 16 538-17 071 Hz ; **V0 = aucune coupure supplémentaire** (~20,5 kHz résiduel) · [Hydrogenaudio wiki LAME](https://wiki.hydrogenaudio.org/index.php/LAME). C'est la base des seuils de mapping rolloff→débit.
- *(Fait)* Un **vrai lossless** (PCM/FLAC/ALAC d'origine) monte jusqu'au Nyquist (~22,05 kHz à 44,1 kHz) **sans falaise**. Un **faux-FLAC** (lossy ré-encodé en conteneur lossless) trahit une **coupure nette bien sous 22 kHz** — exactement la signature du filtre passe-bas de sa source lossy. La méthode est confirmée par un article grand public 2025 : 16 kHz ≈ 128, 19 kHz ≈ 192, ~20 kHz ≈ 320, vrai lossless ~22 kHz · [Headphonesty, 2025-12](https://www.headphonesty.com/2025/12/lossless-music-collection-disguised-mp3s-prove/) *(NB : cet article pousse surtout un classifieur ML non-public + Spek ; on le garde uniquement pour la confirmation des seuils de cutoff, pas pour ses recommandations d'outils — cf. Vérification adversariale).*

**L'algorithme de référence OSS : fakeflac (réimplémentable, pas réutilisable tel quel)**
- *(Fait, vérifié à la source)* `mevdschee/fakeflac` (Python) est l'implémentation OSS la plus simple : **FFT réelle par seconde fenêtrée Hann, spectre moyen sur `min(seconds, 30)`, détection de rolloff** via `find_cutoff(spectrum, freq/50, diff=1.25, limit=1.1)` (seuils de décrochage) ; verdict réel/dégradé, pas de bitrate exact · [fakeflac (GitHub)](https://github.com/mevdschee/fakeflac).
- *(Correction adversariale — Fait)* **fakeflac utilise scipy** (`scipy.io.wavfile.read`, `scipy.fft.rfft`, `scipy.signal.hann`), **PAS « numpy seul »**, et **lit un WAV déjà décodé** (l'utilisateur convertit en amont, ffmpeg externe). L'algo (rfft/Hann/rolloff) est néanmoins **indépendant du décodeur** et **portable vers numpy** (`numpy.fft.rfft` + `numpy.hanning` existent). O2 est donc une **réimplémentation** de la logique fakeflac, pas une copie littérale — et le fait que fakeflac attende un WAV en entrée **renforce** la logique d'O2 : miniaudio remplace exactement le maillon « décodeur externe ».

**Les outils plus riches : multi-signaux et académique**
- *(Fait)* **Lossless Audio Checker** (papier AES, **Convention 139, octobre 2015, paper 9416**, Lacroix/Prime/Remy/Derrien) combine ~9 signaux (coupure nette, plancher de bruit silencieux, trous spectraux, quantification 16-bit, variance de coupure) : **100 % sur upscaling/transcodage, 91,3 % sur upsampling** · [AES e-Library, paper 9416](https://www.aes.org/e-lib/browse.cfm?elib=17972). *(Correction adversariale : la recherche d'origine datait à tort « 2016 » ; date réelle 2015.)*
- *(Fait)* Implémentation publique : [Lossless-Audio-Checker-GUI](https://github.com/emps/Lossless-Audio-Checker-GUI) — détecte upscaling (LSB à zéro / snap quantification 16-bit) et transcodage lossy (contenu spectral s'arrêtant nettement sous Nyquist) ; confiance = poids combiné des signaux.
- *(Fait, attribution corrigée)* L'académique de référence : **D'Alessandro & Shi**, « MP3 bit rate quality detection through frequency spectrum analysis » (11e ACM Workshop on Multimedia & Security, MM&Sec'09, Princeton) : ~**97 %** pour retrouver le débit-source compressé, **99 %** pour détecter un 320 transcodé depuis 128/192 (analyse du spectre haute-fréquence + classifieur SVM, 5 classes 128/192/256/320 CBR/V0) · [ACM DL 10.1145/1597817.1597828](https://dl.acm.org/doi/10.1145/1597817.1597828). *(Correction adversariale : la recherche d'origine créditait « Liu/Shi » — il n'y a pas d'auteur « Liu » ; DOI, venue, méthode et chiffres sont exacts, seul le 1er auteur était inventé.)*
- *(Fait)* L'approche **CNN abandonnée** confirme la limite physique : [penthy (GitHub)](https://github.com/gioypi/penthy) (TensorFlow/Keras, spectrogrammes 16,2-22 kHz / 8 s) atteint ~90 %, est **abandonné**, et **avoue que les MP3 320 kbps contiennent assez de hautes fréquences pour le tromper** → même le ML bute sur la frontière 320/V0. Coût ML disqualifiant (cf. O4).
- *(Fait)* Le rôle central du décodeur dans les outils existants : [audiofakedetectorpro (GitHub)](https://github.com/alessandrocomito/audiofakedetectorpro) — moteur hybride (spectral + auCDtect + vote majoritaire par segments), **décode via FFmpeg vers PCM** + ffprobe pour les métadonnées.

**Le NŒUD réel : le décodage PCM, pas la FFT**
- *(Fait, vérifié dans le code local)* La FFT est gratuite : **numpy 2.4.6 est déjà physiquement présent** dans le venv et le bundle gelé (`_internal/numpy`), tiré **transitivement par pyrekordbox** (uv.lock l.416 ; cf. mémoire projet « pyrekordbox-needs-numpy »). `numpy.fft.rfft`/`numpy.hanning` suffisent → **0 Mo marginal** pour l'analyse.
- *(Fait, vérifié dans le code local)* Le venv **ne contient AUCUN décodeur PCM** : pas de scipy/soundfile/audioread/pydub/cffi. **mutagen** (`service/app/audio.py:18`, `read_audio_metadata`) ne lit **que les tags**, jamais les samples. Donc numpy seul est inutile sans décodeur.
- *(Fait)* **ffmpeg n'est PAS « déjà tiré »** par l'acquisition : [streamrip (GitHub)](https://github.com/nathom/streamrip) requiert ffmpeg installé **séparément** (système), ne le bundle pas. Pas de réutilisation gratuite pour A3.
- *(Fait)* La piste la plus légère cross-OS : [miniaudio sur PyPI](https://pypi.org/project/miniaudio/) — bindings Python **cffi MIT** du C miniaudio, décode **mp3/flac/ogg-vorbis/wav** (**PAS aac/m4a/opus**), **wheels précompilées macOS (arm64 + x86_64) + Windows** (Python 3.10-3.14), **~235-645 kB**, **v1.71 du 2026-04-29**. Décodeur cross-OS léger sans ffmpeg, sans compilateur — clé de la reco.

**Fiabilité : verdict en niveaux de confiance, jamais binaire dur**
- *(Fait)* La méthode distingue **de façon fiable ≤256 d'un lossless**. La **frontière 320-vs-vrai-lossless est intrinsèquement floue** (LAME V0 ne coupe quasi pas ; penthy avoue être trompé par 320) → **limite physique, pas un bug**.
- *(Inférence)* Faux positifs légitimes attendus : masters volontairement band-limités, vieux enregistrements analogiques, genres calmes (ambient/classique) → coupure naturelle <20 kHz sans transcodage. **Aucun taux chiffré trouvé** pour ces cas → à mesurer en POC. → Verdict en **3 niveaux de confiance** avec zone « incertain » explicite.

### Verdict (reco ponytail)

**Choix : O2 — `miniaudio` (décodeur cffi MIT, wheels précompilées cross-OS) décode ~30-60 s de chaque fichier en PCM mono ; `numpy.fft` (déjà bundlé transitivement) fait la rfft fenêtrée Hann, le spectre moyen et la détection de rolloff**, en **réimplémentant** la logique de l'algo OSS de référence fakeflac (rfft/Hann/`min(30s)`/seuils de décrochage). Mapping aux seuils LAME : ≥20 kHz ≈ 320/V0, ~19,4 kHz ≈ 256, ~18,6-19,2 kHz ≈ V2/192, <18 kHz = lossy franc ; verdict « lossy-source probable » si coupure nette <22 kHz dans un conteneur lossless. **Verdict en 3 niveaux de confiance, jamais binaire dur.**

- **Rationale (Ponytail)** : c'est le **premier barreau qui tient réellement**. Barreau 1 « ne pas faire » (O0) et barreau « dépendance déjà bundlée suffit » échouent car **RIEN dans le venv ne décode l'audio en PCM** (mutagen = tags seulement, vérifié) — la FFT seule via numpy est inutile sans samples. O1 tags-only **rate la coupure spectrale**, donc rate le cœur d'A3. **miniaudio est l'ajout minimal qui débloque le décodage** : une petite dépendance (~235-645 kB), MIT, wheels prêtes, et la FFT reste gratuite via numpy. On évite le barreau le plus coûteux (ffmpeg, +70-100 Mo) et le ML (+200-500 Mo). C'est le minimum qui produit un **vrai** verdict A3.
- **Non-négociables tenus (§3)** : **§3.3** — audio lu en **read-only** sur le **chemin résolu (§3.2)**, `Path.exists`/`stat` d'abord (réutiliser le pattern TCC-safe de `service/app/audio.py:131`), ouverture par miniaudio en lecture seule, **AUCUN déplacement/copie**, jamais de listing de dossier cloud. **§3.1** — A3 est **strictement read-only**, n'est **JAMAIS** appelé dans l'unit-of-work `_mutate` (`assert_rekordbox_can_mutate`, adapter.py:172), n'ouvre jamais master.db en écriture. **§3.5** — 100 % local, aucun réseau, certifi/secrets non concernés. **§3.7** — wheels officielles macOS (arm64 + x86_64) + Windows py3.10-3.14, venv py3.14 couvert, **aucun compilateur**. **§3.8** — libellés de verdict (3 niveaux) à ajouter aux locales FR/EN.
- **Coût sidecar** : **≈2-3 Mo** (miniaudio ~235-645 kB + cffi ~1 Mo + **pycparser** ~1 Mo) sur un sidecar de ~81-120 Mo dominé par numpy (23 Mo) + sqlcipher3 (6,4 Mo) — soit ~2-3 %. **CPU/RAM** : ~30-60 s de PCM mono + une rfft fenêtrée = quelques dizaines de Mo RAM transitoire et **<0,5 s/fichier**, parallélisable.

**Ce que ça écarte** : (1) O0/YAGNI (rate le cœur d'A3, contredit OVERHAUL-01 §8 qui liste A3 en v1) ; (2) O1 tags-only (ne voit pas la coupure) ; (3) O3 ffmpeg embarqué (+70-100 Mo, casse §2(2)) ; (4) O4 ML (+200-500 Mo, abandonné, trompé par 320).

**Upgrade-path (`addWhen`)** : n'ajouter **ffmpeg (O3) QUE si** les fichiers **AAC/m4a/opus** deviennent un cas réel et fréquent de l'acquisition F3 (miniaudio ne décode pas l'AAC) — et alors **ffmpeg système optionnel** (détecté, OFF si absent), **jamais embarquer le binaire** (casserait §2(2)). Le ML (O4) reste exclu. Cette nuance est cohérente avec la décision « no local audio analysis » (qui vise l'enrichissement energy/key/BPM, **pas** le diagnostic spectral d'hygiène — les deux coexistent).
