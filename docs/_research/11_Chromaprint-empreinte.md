### Constat (faits sourcés)

**Ce qu'est Chromaprint et ce que vise A2**
- Chromaprint est la lib C de référence de l'écosystème AcoustID/MusicBrainz pour l'empreinte acoustique « near-identical » (dedup de fichiers, encodages alternatifs). L'empreinte est un tableau d'entiers 32 bits (~32 octets/seconde d'audio), calcul de l'ordre de la centaine de ms pour 2 min · cible near-identical/dedup et ordre de grandeur de débit **vérifiés à la source dans `chromaprint.h` et la page principale [acoustid.org](https://acoustid.org/)** (et NON sur `/chromaprint`, voir réserve de sourçage). La page [acoustid.org/chromaprint](https://acoustid.org/chromaprint) confirme l'algorithme propriétaire, l'exigence FFmpeg pour builder, et les paquets binaires Linux/macOS/Windows.
- Dans A2, l'empreinte est la **3e strate** de dedup, après ISRC exact (§5.3) et fuzzy titre/artiste/durée (seuil 0.87, §5.4). Elle n'attrape que le **résiduel** : même enregistrement, **ISRC absent ET** métadonnées trop divergentes pour le fuzzy (ré-encodage / rip différent sans tags). Sur une collection Rekordbox bien taguée, ce résiduel est étroit.

**Licence : le piège est dans le binaire, pas dans le code**
- Le code propre de Chromaprint est MIT, **mais** le projet embarque du code FFmpeg LGPL 2.1 ; verbatim : *« as a whole, Chromaprint should be therefore considered to be licensed under the LGPL 2.1 license »* (intention future de retirer FFmpeg pour passer en MIT pur) · [LICENSE.md du repo](https://github.com/acoustid/chromaprint/blob/master/LICENSE.md).
- Le choix de FFT change la licence du binaire final : **FFTW3 = GPL** (contaminant), **KissFFT = permissif**, **FFmpeg = LGPL** et sert AUSSI au **décodage/resampling audio** dans `fpcalc` · [README du repo](https://github.com/acoustid/chromaprint/blob/master/README.md).
- **Conséquence factuelle (réfutation directe de l'overhaul)** : les binaires `fpcalc` officiels sont buildés **avec FFmpeg statique audio-only** ([acoustid/ffmpeg-build](https://github.com/acoustid/ffmpeg-build), « static audio-only FFmpeg builds used for Chromaprint packaging », MIT côté scripts de build). Ils sont donc **LGPL 2.1, PAS permissifs**. L'affirmation `OVERHAUL-01-valeur-features.md` ligne 225 « KissFFT garde Chromaprint permissif » est **factuellement fausse pour les binaires officiels** : KissFFT ne rend le binaire permissif que si l'on **recompile soi-même** chromaprint en excluant FFmpeg — mais alors `fpcalc` **perd son décodeur audio**. À amender dans l'overhaul (cf. recommandation des sceptiques).
- Bon point : `fpcalc` embarque un FFmpeg **audio-only** (~1,8–2,6 Mo packagé), **pas** le FFmpeg complet (dizaines de Mo). La reco évite donc le piège du natif lourd caché.

**Tailles des paquets `fpcalc` 1.6.0** (release v1.6.0 publiée **2025-08-28**, archives compressées tar.gz/zip) · [GitHub release API latest](https://api.github.com/repos/acoustid/chromaprint/releases/latest)
- macOS arm64 1,29 Mo · macOS universal **2,64 Mo** · macOS x86_64 1,35 Mo · Linux x86_64 2,40 Mo · Linux arm64 1,41 Mo · **Windows x86_64 1,82 Mo**.
- **Réserve** : ce sont les **archives compressées de release**. Le poids **non compressé** réellement ajouté au bundle PyInstaller (avant/après UPX, activé dans le `.spec`) **n'est pas mesuré** → POC requis avant promotion.

**Le point dur : comparer localement ≠ produire l'empreinte**
- `pyacoustid` 1.3.1 (publiée **2026-04-09**, MIT, Python ≥3.10, dépend de `audioread`+`requests`) expose `compare_fingerprints(a, b)` (introduit en 1.3.0, partie comparaison en **Python pur**) · [PyPI pyacoustid](https://pypi.org/project/pyacoustid/).
- Mais `compare_fingerprints` lève `ModuleNotFoundError('function needs chromaprint')` et appelle `chromaprint.decode_fingerprint(...)` **avant** de déléguer à `_match_fingerprints` (XOR + popcount, score [0,1], Python pur) · [acoustid.py (master)](https://raw.githubusercontent.com/beetbox/pyacoustid/master/acoustid.py).
- Et `chromaprint.decode_fingerprint` **bind le natif via ctypes** (`_guess_lib_name`/`_load_library` → `ctypes.CDLL`), **sans aucun fallback Python** (sinon `ImportError`) · [chromaprint.py (master)](https://raw.githubusercontent.com/beetbox/pyacoustid/master/chromaprint.py).
- **Donc** : avec l'API `pyacoustid`, le binaire `fpcalc` **seul ne suffit pas** à comparer — il faut **aussi** la **lib dynamique** `libchromaprint`. **Contournement vérifié à la source** : `fpcalc -raw -signed` sort directement les **entiers décodés** (séparés par virgules) — flags `g_raw`/`g_signed` confirmés dans `src/cmd/fpcalc.cpp`. La partie native (`decode_fingerprint`) devient **inutile** ; on aligne + XOR + popcount avec numpy en réutilisant le pattern `_match_fingerprints`.

**La comparaison est 100 % locale (aucune base AcoustID, aucun réseau)**
- `soundalike` (Go) trouve les doublons via `fpcalc`/Chromaprint **entièrement en local** : *« No network requests are made to AcoustID or other APIs »* ; matching en 2 phases (lookup 16-bit défaut 0.25, puis comparaison bit-à-bit toutes alignements, conservé si **> 0.95 bits identiques** par défaut) · [soundalike (Codeberg)](https://codeberg.org/derat/soundalike). La base web AcoustID est **inutile** pour du dedup intra-collection.
- `beets` `chroma`/`chromasearch` fait du dedup local d'encodages alternatifs / métadonnées manquantes via pyacoustid + `fpcalc` sur le PATH, mais **prévient** : le fingerprinting coûte « significantly more CPU and memory », les imports « will go substantially slower » · [beets chroma](https://beets.readthedocs.io/en/stable/plugins/chroma.html).
- Chromaprint **n'expose pas** de fonction publique de comparaison (jugée application-specific) : comparer = aligner puis calculer le bit-error-rate ; le seuil dépend de la précision voulue et **les faux positifs croissent avec la taille de la base** · [acoustid Google Groups (uz1-LuaaXCA)](https://groups.google.com/g/acoustid/c/uz1-LuaaXCA).

**Maintenance pyacoustid (corrigé)**
- `pyacoustid` 1.3.1 est daté **2026-04-09** sur PyPI. La page [Snyk](https://snyk.io/advisor/python/pyacoustid) affiche désormais une maintenance **`HEALTHY`** (>10 contributeurs, release dans les 3 derniers mois) — l'ancien claim « inactive » **ne tient plus** (voir Vérification adversariale). Le risque résiduel réel est une **cadence de release lente/irrégulière** (bus-factor), pas une inactivité.

> **Réserve de sourçage** : les chiffres de débit/empreinte (« ~100 ms pour 2 min », « ~2,5 ko », cible near-identical) avaient été attribués à `acoustid.org/chromaprint` ; le fond est vrai mais l'ancre exacte est la **page principale acoustid.org + `chromaprint.h`** (array int32, ~32 octets/s). Correction de citation, pas de contenu.

### Verdict (reco ponytail)

**Choix : Option 0 en v1 — NE PAS implémenter A2.** A2 ne franchit même pas le **1er barreau** du lens ponytail (« la brique doit-elle exister ? »). La dedup a déjà **deux strates qui marchent** : ISRC exact (§5.3) + fuzzy (§5.4, seuil 0.87). La 3e strate empreinte n'attrape qu'un **résiduel étroit** (même enregistrement, ISRC absent **et** fuzzy en échec) et **force un binaire natif tiers LGPL 2.1** au sidecar — ce qui heurte frontalement §2(2) « empreinte légère ». La chose la plus paresseuse qui tienne : **ne pas la construire, poser un repère `ponytail:` et l'ajouter si la valeur terrain le justifie.**

**Si/quand A2 est justifié par la valeur terrain → Option A**, derrière un **flag OFF par défaut** :
- Embarquer le binaire `fpcalc` officiel (1 par OS/arch : mac universal + win x64) via PyInstaller `--add-binary`, résolu par `sys._MEIPASS`.
- **NE PAS** dépendre de `chromaprint.decode_fingerprint` (exige la lib dynamique, ctypes fragile). **Utiliser `fpcalc -raw -signed`** → entiers décodés directement (vérifié dans `fpcalc.cpp`), **pas besoin** de réimplémenter un décodeur delta+RLE Python ni la lib dynamique `libchromaprint`. Réutiliser le pattern `_match_fingerprints` de pyacoustid (alignement + XOR + popcount) **porté sur numpy** (déjà bundlé via pyrekordbox).
- Lecture **seule** : passer à `fpcalc` un **chemin absolu** issu de `Path.exists()`, **ne JAMAIS déplacer** le fichier. La seule écriture éventuelle (soft-delete d'un doublon) reste dans l'unit-of-work `_mutate` existant (gardé par `app/safety.py:assert_rekordbox_can_mutate()`).
- Seuil de départ **~0.95 bits identiques** (défaut soundalike) — **à calibrer empiriquement** sur faux positifs (ce n'est PAS une valeur académique, voir POC).

**Ce qu'on écarte** : (1) **Option B** (lib dynamique + ctypes) — même résultat fonctionnel mais **2 natifs** au lieu d'1, et la surface la plus risquée sous PyInstaller (RPATH macOS, codesign de `.dylib`/`.dll`) ; à ne considérer que si le décodage via `fpcalc -raw` s'avère trop coûteux à maintenir. (2) **Option C** (empreinte maison) — il faut **quand même** un décodeur audio natif (ni numpy/mutagen/pyrekordbox ne décodent l'audio compressé), donc on paie le poids de A/B **sans** la robustesse éprouvée de Chromaprint ; réinventer un algo robuste au ré-encodage viole §2(1). (3) la base web AcoustID (inutile, dedup intra-collection).

**Déclencheur de promotion v1 → A** : mesurer sur une **vraie collection** le volume de doublons ratés par ISRC+fuzzy. Si non négligeable → activer A. **Évaluer A2 ET A3 ensemble** : A3 (faux-320/FFT) impose **le même décodeur audio natif** (fpcalc/ffmpeg). Si A3 entre en v1, le binaire natif arrive de toute façon → le surcoût marginal d'A2 tombe à **~0 octet**, ce qui change le calcul de promotion. Si A3 sort de v1, A2 reste à 0 Mo comme recommandé.
