### Constat (faits sourcés)

> **Réserve de sourçage** : les 5 sources primaires sont des fichiers réels au **tag v2.2.0** (raw.githubusercontent), recoupées verbatim par le sceptique SOURCES. Là où la recherche d'origine était imprécise (certifi, date #846, issue #818, SHA 189acda), les faits sont corrigés ci-dessous.

**`streamrip` (lib Python, pas la CLI) — candidat recommandé**
- Downloader scriptable **GPL-3.0-only** ([`nathom/streamrip`](https://github.com/nathom/streamrip)), ~4 700 ★. Dépôt **réellement maintenu** : tag **v2.2.0 daté 2026-03-12**, dernier commit avril 2026. Services : Qobuz/Tidal/Deezer/SoundCloud (+ Spotify/Apple via Last.fm). · *Fait, source primaire.*
- **PIÈGE MAJEUR : PyPI est figé à v2.1.0 (2025-03-10)**, qui contient encore le bug de parsing d'URL Deezer → `pip install streamrip` ne donne PAS le correctif. L'embarquement **EXIGE un pin sur le tag git v2.2.0**, pas `pip install`. · *Fait, [PyPI streamrip](https://pypi.org/project/streamrip/) figé 2.1.0 / 2025-03-10, corroboré par #865 dont le reporter est sur 2.1.0.*
- **SHA du tag : à résoudre, NON traité comme vérifié ici.** La recherche d'origine affirmait « commit `189acda` figé », mais le mapping `refs/tags/v2.2.0` → SHA **n'a pas été prouvé** dans cette recherche. À résoudre explicitement (`git ls-remote --tags` / API GitHub) **avant** de figer au lockfile. · *Correction (sceptique SOURCES + open_risk).*
- **API d'embarquement v2 officielle et documentée** (wiki, pas du reverse) : on construit un `Config` via `Config.defaults()`, on instancie un client par service (`DeezerClient`, `SoundcloudClient`, `QobuzClient`, `TidalClient`), `await client.login()`, puis on passe par les objets `Pending*` (`PendingSingle`/`PendingTrack.resolve() -> Track`) avant `await track.download()`. Tout est **async (aiohttp)**. · *Fait, [wiki Scripting-with-Streamrip-v2](https://github.com/nathom/streamrip/wiki/Scripting-with-Streamrip-v2), consulté 2026-06-16.*
- **D18 satisfait PAR L'API** : `track.download_path` est le vrai chemin sur disque. `Track` est `@dataclass(slots=True)` ; `download_path` initialisé `''`, posé par `_set_download_path()` (`os.path.join(folder, …)`), puis **réassigné `self.download_path = engine.final_fn` après conversion ffmpeg** → chemin réel. · *Fait, [media/track.py@v2.2.0](https://raw.githubusercontent.com/nathom/streamrip/v2.2.0/streamrip/media/track.py), consulté 2026-06-16.*
- **La CLI ne tient PAS D18 proprement** : `rip url`/`rip id` n'exposent **aucune sortie JSON/machine-lisible ni report du chemin de fichier** ; stdout = `rich`/progress non parsable → on retomberait sur la reconstruction de nom, **interdite par SPEC-UNIFIED §5.5/D18 (F1)**. · *Fait, [README v2.2.0](https://github.com/nathom/streamrip), consulté 2026-06-16.*
- **Isolation d'état (F2/F3) tenue par instance** : `Config.defaults()` instancie via `cls(BLANK_CONFIG_PATH)`, `file`/`session` séparés par `copy.deepcopy` ; `session.deezer.arl`, `session.soundcloud.client_id`+`app_version`, et `session.downloads.folder` sont **modifiables par instance** → un `Config` par job = **zéro état global de process**. · *Fait, [config.py@v2.2.0](https://raw.githubusercontent.com/nathom/streamrip/v2.2.0/streamrip/client/config.py), consulté 2026-06-16.*
- **Stack de deps** : `mutagen ^1.45.1` (déjà bundlé côté Syncbox → réutilisé), `pycryptodomex ^3.10.1` (namespace `Cryptodome`, ≠ `Crypto` → pas de collision PYZ ; Blowfish en import statique capté par PyInstaller), `deezer-py 1.3.6` (épinglé EXACT, **pas 1.3.7**), `aiohttp ^3.9`, `aiodns`, `aiolimiter`, `aiofiles`, `m3u8 ^0.9`, `rich ^13.6`, `Pillow >=9<11`, `tomlkit`, `pathvalidate`, `appdirs`, deps CLI (`simple-term-menu`/`pick`/`windows-curses`, `click-help-colors`). · *Fait, [pyproject.toml@v2.2.0](https://raw.githubusercontent.com/nathom/streamrip/v2.2.0/pyproject.toml), consulté 2026-06-16.*
- **certifi : embarqué par défaut, pas purement optionnel.** Correction de la recherche d'origine : le pyproject v2.2.0 liste `certifi` **DEUX FOIS** — en dépendance régulière (`certifi = "^2025.1.31"`) ET sous `[tool.poetry.extras] ssl = ["certifi"]`. Le garde-fou §3.5 « forcer certifi » est donc trivial (certifi déjà câblé côté Syncbox via `httpx/_config.py load_verify_locations(certifi.where())`), et l'ancien risque « vérifier qu'il est activé » est **abaissé à une simple confirmation**. · *Correction (sceptique SOURCES), source pyproject.toml@v2.2.0.*
- **Aucun binding ffmpeg Python.** ffmpeg est un **binaire externe** appelé en sous-process. · *Fait, pyproject.toml@v2.2.0 + README.*

**Le coût ffmpeg vient UNIQUEMENT de SoundCloud (HLS MP3) — hors périmètre v1**
- SoundCloud sert du **HLS `audio/mpeg`** standard et **exige ffmpeg externe** pour concaténer/convertir (`downloadable.py` : `if shutil.which("ffmpeg") is None: raise Exception("FFmpeg must be installed.")` + `concat_audio_files(..., "mp3")` en sous-process asyncio). · *Fait, downloadable.py@v2.2.0, confirmé verbatim par le sceptique SOURCES.*
- SoundCloud **sans compte** : `client_id` + `app_version` **auto-scrapés** de la home SoundCloud par `_refresh_tokens()` (regex `client_id:"(\w+)"`, `window.__sc_version`), aucun OAuth/Go+. Formats : HLS MP3 standard (~128 kbps), `ORIGINAL_DOWNLOAD` (qualité d'origine) **seulement si l'uploader l'a activé**, sinon `NON_STREAMABLE`. `login()` rafraîchit et **persiste via `file.set_modified()`** → à intercepter pour §3.6. · *Fait, [soundcloud.py@v2.2.0](https://raw.githubusercontent.com/nathom/streamrip/v2.2.0/streamrip/client/soundcloud.py), consulté 2026-06-16.*
- **Conséquence (refutation du sceptique non-négociables)** : un ffmpeg statique ~40-80 Mo **par plateforme** (mac arm64+x86_64 ET Windows) **doublerait quasi** un sidecar aujourd'hui à 62 Mo, plus un point dur cross-OS (résolution PATH en binaire PyInstaller gelé) → **frontalement contraire à §2.2 (légèreté) et §3.7**. **Deezer-seul (FLAC/MP3 servi direct, pas de HLS) n'exige PAS ffmpeg.** Retirer SoundCloud de v1 **élimine le coût ffmpeg**. · *Fait + Inférence dimensionnement bundle (dist 62 Mo : numpy 6,6 + sqlcipher3 6,4 + libcrypto 4,6 + rapidfuzz 4,3).*

**Risque supply-chain (full-track + sécurité)**
- L'API officielle Deezer **limite l'accès à des previews de 30 s** ; le full-download est précisément ce que le package malveillant **`automslc` contournait illégalement** → impose **pin strict + audit du code embarqué**. · *Fait, [Socket.dev, 2025-02-25](https://socket.dev), corroboré BleepingComputer / The Hacker News.*
- Fragilité auth Deezer 2025-2026 : changement de format d'URL ([issue #865, ouverte 2025-06-23](https://github.com/nathom/streamrip/issues/865), `dzr.page.link` → `link.deezer.com/s/…`, « Found invalid url … skipping ») et auth errors multi-ARL ([issue #846, ouverte 2025-04-24](https://github.com/nathom/streamrip/issues/846), changement de chiffrement de token fin 2024). · *Fait. **Correction** : #846 datée 2025-04-24 ; **issue #818 retirée** (citée en prose de la recherche d'origine, jamais vérifiée ni porteuse — #846/#865 suffisent).*
- **Ces issues prouvent SEULEMENT la fragilité auth/URL, PAS qu'un FLAC/MP3 complet (vs preview 30 s) est obtenable en 2025-2026.** La viabilité full-track reste **un pari** → POC#6 porte bloquante. · *Inférence prudente.*

### Synthèse — options et trade-offs

> **RECO PONYTAIL EN TÊTE** (détaillée en fin de section). **Option B corrigée en Deezer-only pour v1** : `streamrip` importé comme lib, pin git v2.2.0, derrière une interface mince `DeezerAcquirer.download(track_id) -> Path`, via `Config.defaults()` par job → `await client.login()` → `PendingSingle.resolve()` → `await track.download()` → `track.download_path`. **SoundCloud (`SoundcloudAcquirer`) renvoyé en B4** (plus tard), car il tire ffmpeg externe — scope creep non validé et coût §2.2/§3.7.

| Option | Ce que c'est | D18 | F2/F3 | Sidecar | Verdict |
|---|---|---|---|---|---|
| **A — Sous-process CLI** (`rip url`/`rip id`) | Invoquer le binaire en sous-process par job, parser stdout, deviner le fichier | **CASSE D18** : aucune sortie machine-lisible → reconstruction de nom (F1, interdit §5.5) | Corrélation par index de liste fragile | Même arbre de deps + entry-point CLI à packager 2 OS, **aucun gain de poids** | **Rejetée** : viole D18 ; §3.6 (CLI lit l'ARL depuis `config.toml` sur disque) |
| **B — API Python embarquée (RECO, Deezer-only v1)** | Importer comme lib, pin git ; `Config.defaults()` par job, `PendingSingle.resolve() -> Track.download() -> download_path` | **D18 RÉEL** (`track.download_path`) | **Corrigés** : `Config` par instance, zéro global ; corrélation par `track_id` | aiohttp + stack async + Pillow + tomlkit + pathvalidate + deezer-py 1.3.6 ; mutagen réutilisé. **ffmpeg seulement si SoundCloud (→ exclu v1)** | **Retenue** |
| **C — Vendoriser + élaguer** au strict Deezer | Copier `client/deezer.py`, `Downloadable`, `media/track.py`, config, db ; retirer Qobuz/Tidal/CLI/rich | D18 idem B | F2/F3 idem B | Plus léger (retire clients/CLI/rich) mais toujours aiohttp + pycryptodomex + deezer-py | **Cible de bascule seulement** : GPL toujours dû ; **dette de re-port des fixes Deezer** (la raison même de choisir streamrip) → aggrave le garde-fou maintenabilité §2 |

**Alternative de lib conservée (NON close)** : `deemix-fork` (vietsman/buoyantbeaver). D18 le plus net (`download()` → `{'path': str(writepath)}`), **pas d'aiohttp** (requests) → bundle plus léger, mais mainteneur fantôme et viabilité non garantie. SPEC-UNIFIED §6.5 « choix de lib délégué au POC » et §8 #6 « trancher l'arbitrage lib AVANT de figer la lib » → **streamrip = défaut documenté, départagé d'avec deemix-fork APRÈS POC#6**, pas tranché à l'overhaul. · *Correction (sceptique non-négociables), source [10_Acquisition-2026.md](./10_Acquisition-2026.md) l.19-22/57-59.*

### Reco ponytail

**Choix : Option B — `streamrip` importé comme bibliothèque, pin git v2.2.0 (SHA `refs/tags/v2.2.0` à résoudre et figer au lockfile), enveloppé derrière une interface mince `DeezerAcquirer.download(track_id) -> Path`. v1 = DEEZER UNIQUEMENT.** Chemin canonique par job : `Config.defaults()` → poser `session.deezer.arl` + `session.downloads.folder` **en mémoire sur l'instance** → `await client.login()` → `PendingSingle(id, client, config, db).resolve()` → `await track.download()` → retourner `track.download_path`. **Télécharger par ID numérique** (résolu depuis l'ISRC), **jamais par URL courte** (contourne #865). `SoundcloudAcquirer` est **différé en B4** (tire ffmpeg externe).

- **Pourquoi le plus paresseux qui tient** : c'est le barreau le plus bas qui satisfait D18 réellement — seul l'embarquement API expose `track.download_path` (vrai chemin), là où la CLI (A) force la reconstruction de nom interdite par §5.5. Réutiliser un downloader mûr et vivant derrière une interface mince est plus paresseux que vendoriser (C, dette de re-port) ou réécrire la chaîne gw-light → token → CDN → Blowfish. `mutagen` est déjà bundlé. On ne descend pas plus bas (stdlib/OS) car aucun OS ni Rekordbox ne télécharge depuis Deezer.
- **Non-négociables tenus** : **D18** par `track.download_path` (API, pas reconstruction). **F2/F3 corrigés** — `Config` par instance porte `arl`/`downloads.folder` par job, jamais en global (corrige le bug réel actuel : `acquisition.py:59 _applied_arl` global + `acquisition.py:54 _STATUS_CACHE` module-level). **§3.6** : ARL posé en mémoire sur l'instance `Config` depuis keyring (si signé) / store chiffré (sinon), **JAMAIS écrit dans `config.toml`** — corrige le `deemix_arl` actuellement en clair dans les settings SQLite ([settings.py:118](../../service/app/repositories/settings.py)). **§3.5** : certifi déjà embarqué (dépendance régulière du pyproject, pas extra) → simple confirmation. **§3.1** : module 100 % hors du chemin `_mutate` master.db. **§3.3** : écriture en staging + lecture via `Path.exists`, ne déplace rien (= mécanique §5.5 `downloaded → ready`). **GPL-3.0-only confiné** au module optionnel, OFF par défaut.
- **Coût sidecar (v1 Deezer-only)** : surcoût dominé par la **stack async** (aiohttp, aiodns, aiolimiter, aiofiles, m3u8) + Pillow + tomlkit + pathvalidate + deezer-py 1.3.6 ; pycryptodomex/mutagen réutilisent le socle (mutagen déjà bundlé). **ffmpeg ÉVITÉ en v1** (Deezer sert direct, pas de HLS) → §2.2/§3.7 préservés, ~40-80 Mo/plateforme et le packaging cross-OS de ffmpeg évités. Module OFF par défaut → ne grève le binaire de base que si l'utilisateur active l'acquisition (idéalement plugin téléchargeable hors sidecar de base). **Réserve §2.2** : aiohttp réintroduit une 2e pile HTTP là où Syncbox a déjà httpx async (certifi câblé) — pas un non-négociable cassé, mais c'est précisément pourquoi `deemix-fork` (requests, pas aiohttp) reste l'alternative plus légère à départager au POC.
- **Chemin d'upgrade** : ajouter **SoundCloud (B4) + ffmpeg** seulement si demande réelle, idéalement en plugin téléchargeable hors sidecar de base ; Qobuz/Tidal supportés par la même API si demandés (coût marginal nul). Basculer vers vendorisation élaguée (C) ou `deemix-fork` UNIQUEMENT si l'API interne (`Track`/`PendingSingle`, non documentée) casse de façon répétée à l'upgrade, OU si le poids aiohttp devient bloquant — **arbitrage lib tranché au POC, pas rouvert sans raison**.

### Risques ouverts

1. **[PORTE BLOQUANTE — POC#6] Deezer full-track non prouvé.** La viabilité d'un **FLAC/MP3 COMPLET (vs preview 30 s)** avec un ARL Premium courant n'est PAS prouvée 2025-2026. Issues #846 (2025-04-24) / #865 (2025-06-23) documentent auth errors et changement de chiffrement de token fin 2024 ; Socket.dev (2025-02-25) confirme la restriction 30 s côté API officielle. **Aucune source ne prouve le full-track 2026** → POC empirique macOS+Windows obligatoire **avant** de verrouiller Fork D et la lib. B1 reste **au stade POC, pas « prêt à écrire »**.
2. **[RISQUE DOMINANT — maintenabilité, garde-fou co-égal §2]** API d'embarquement = **API interne non documentée hors-wiki** : `Track` est `@dataclass(slots=True)` **non-constructible standalone** (exige `meta`+`downloadable`+`config`+`folder`+`cover_path`+`db`) ; seul chemin légitime = `PendingSingle`/`PendingTrack.resolve()`. `slots=True` **interdit le monkeypatch d'amortissement** → casse silencieuse possible à l'upgrade ; **le wrapper n'est PAS trivial** (l'affirmation « API coûteuse » est confirmée). **Condition dure**, pas note de bas de page : pin commit STRICT figé au lockfile + tests d'intégration obligatoires survivant à un bump de commit, wrapper via `PendingSingle.resolve() -> Track.download()` (jamais de `Track` instancié à la main).
3. **SHA du tag à résoudre et figer.** v2.2.0 = tag git absent de PyPI (2.1.0 = parser cassé). Reproductibilité non garantie tant que le SHA de `refs/tags/v2.2.0` n'est pas résolu (`git ls-remote` / API GitHub) **et** figé dans le lockfile uv/poetry. Ne PAS traiter `189acda` comme vérifié.
4. **ffmpeg externe (uniquement si SoundCloud/B4).** Pas dans les deps Python ; binaire ~40-80 Mo/plateforme à packager/résoudre macOS+Windows. **Traité en v1 par exclusion de SoundCloud** ; à rouvrir comme dépendance native du plugin B4 seulement.
5. **client_id/app_version SoundCloud (B4) auto-scrapés** et « changent périodiquement » → dépendance fragile au JS SoundCloud, persistés via `set_modified()` → à intercepter pour ne pas écrire sur disque (§3.6). Hors v1.
6. **Qualité SoundCloud (B4)** : flux standard HLS MP3 ~128 kbps ; `ORIGINAL_DOWNLOAD` seulement si l'uploader l'a activé. Hors v1.
7. **DMCA / supply-chain** : précédent Deezer 2021 + rappel `automslc` (Socket.dev 2025-02-25). Confiner GPL au module optionnel OFF par défaut, idéalement plugin séparé, auditer le code embarqué.
8. **certifi (§3.5)** : **abaissé de risque à confirmation** — certifi est dépendance régulière du pyproject v2.2.0 (`^2025.1.31`) ET extra `ssl`, déjà bundlé côté Syncbox ; forcer explicitement pour tout HTTPS sortant du module, vérifier en POc sur binaire gelé.
